Changes in v2, for the cover letter ("EDITME" of `b4 prep --edit-cover`). Check
the hardware line against what was really tested before sending.

Changes in v2:
- From the review of Thomas Zimmermann:
  - No cursor plane, and no blending in the driver.
  - No vblank timer, and so no vblank support.
  - The EDID is not kept: it is read from the monitor on every probe.
  - The formats are XRGB8888, converted to RGB888, and RGB565, sent as it is. The
    10-bit ones went: they are not native (the device takes RGB888 or RGB565),
    and they were only converted down. What the USB link cannot carry at a mode
    fails in the atomic check of the plane; the CRTC no longer picks a format.
  - The limits are what the timing registers hold, 12 bits (4095).
  - mode_fixup adjusts the clock, mode_valid returns MODE_* codes, the helpers are
    used as drop-ins, and the plane helper goes first in the plane check.
  - The interrupt endpoint is only polled once the device is registered, and
    after system sleep once the state is restored, so no state about that in the
    driver. The chips themselves are still set up before restoring the state,
    as restoring it writes to them.
  - Forcing the monitor sense went to the HDMI encoder, and the CRTC only enables
    the interrupts about frames.
  - struct fl2000_device, sorted driver flags, drm_dbg(), fewer comments.
- Bind through interface 0 and claim the other two with
  usb_driver_claim_interface(), with everything hanging off that binding,
  instead of keeping shared state on the usb_device: unloading the module or
  unbinding the driver left it all behind, pointing into freed memory. This
  answers question 3 of v1, which is gone. There is no component framework any
  more, the bridge is attached directly, and the DRM device hangs off the
  interface.
- USB resets no longer unbind the driver (.pre_reset/.post_reset).
- Keep the stream as long as the DRM device, and guard everything that reaches
  a register with drm_dev_enter() or drm_bridge_enter().
- Really probe for the IT66121: the detection had its return values inverted and
  always "found" the chip at the first address, without any transfer.
- Reject modes larger than the limits in the CRTC check. The core only applies
  max_width/max_height to probed modes, and a mode with an off-screen primary
  plane could wrap the 32-bit buffer size.
- Do not write the old shadow frame with a new geometry after a failed mode set.
- Remove the EDID read through the IT66121 DDC engine, which never completes on
  these boards and cannot work behind an I2C engine that reads whole dwords (each
  read of the DDC status pops the DDC FIFO). The DDC bus release stays.
- Honour the plane's source rectangle: a framebuffer larger than the mode froze
  the output.
- No phantom VGA monitor from the forced monitor sense when HDMI is unplugged.
- Acknowledge the IT66121 from the FL2000 interrupt and unmask its hot plug,
  instead of polling it over USB ten times a second. Enable the monitor interrupts
  at probe, not at the first mode set.
- Keep FL2000 resets and I2C control register writes out of running I2C
  operations.
- Smaller fixes: URB submission retries bounded (-EAGAIN looped forever), no
  pointer in urb->transfer_buffer, flush_kernel_vmap_range() before sending a
  frame, I2C message validation through the adapter quirks, a lost status event
  when clearing the LBUF flags, interrupt URB interval and endpoint, a NULL
  dereference on allocation failure, suspend error handling.

Most of these come from the Sashiko review of v1.
